WSL ↔ Windows 跨端训练环境配置指南

  为什么这样用？

  你的 GPU 驱动（NVIDIA CUDA）在 Windows 侧，conda 环境 dl_lab1 里的 PyTorch 也是 Windows
  原生编译的（torch 2.6.0+cu124）。WSL 虽然能挂载 D 盘（/d/），但 WSL 内部没有 GPU 驱动，在 WSL
  里直接调用 /d/Software/miniconda3/.../python.exe 会失败——因为 Windows PE 可执行文件不能直接在
  Linux 内核上运行。

  所以正确路径是：WSL → powershell.exe → Windows Python.exe → CUDA → GPU。

  ---
  环境拓扑

  ┌─ WSL2 (bash) ─────────────────────────────┐
  │                                            │
  │  /d/Software/miniconda3/envs/dl_lab1/      │
  │       ↕ 同一个文件系统 (DrvFs 挂载)          │
  │  D:\Software\miniconda3\envs\dl_lab1\      │
  │                                            │
  │  bash -i -c 'powershell.exe -Command ...'  │
  │       │                   │                │
  │       ▼                   ▼                │
  │  ┌──────────┐    ┌──────────────────┐      │
  │  │ bash -i  │    │ Windows 侧执行    │      │
  │  │ 加载别名  │    │ python.exe ←→ GPU │      │
  │  └──────────┘    └──────────────────┘      │
  └────────────────────────────────────────────┘

  关键在于 bash -i：不加 -i 时 bash 以 non-interactive 模式运行，不会加载 ~/.bashrc，你的
  powershell.exe 别名就不可见，命令直接报 command not found。加上 -i 后 bash 加载完整
  profile，别名生效。

  ---
  三种使用模式

  模式 1：WSL 发命令调 PowerShell（临时验证用）

  # 检查 PyTorch 版本和 CUDA
  bash -i -c 'powershell.exe -Command "& D:\Software\miniconda3\envs\dl_lab1\python.exe -c \"import
  torch; print(torch.__version__, torch.cuda.is_available())\""'

  # 跑一个 Python 脚本
  bash -i -c 'powershell.exe -Command "& D:\Software\miniconda3\envs\dl_lab1\python.exe
  D:\Workspace\DL_HW\LAB4\test_run.py --data_ratio 0.05"'

  # 编译 LaTeX
  bash -i -c 'powershell.exe -Command "& D:\Software\texlive\2026\bin\windows\xelatex.exe
  -output-directory=D:\Workspace\DL_HW\LAB4 D:\Workspace\DL_HW\LAB4\LAB4_report.tex"'

  适用场景：在 WSL 里临时跑一条命令看结果。不适合长时间训练——WSL 终端会一直被占用。

  注意事项：路径必须用 Windows 格式（D:\...），不能用 /d/...。因为命令最终是 powershell.exe
  解析的，它在 Windows 命名空间里运行。

  模式 2：PowerShell 直接跑 PS1 脚本（正式训练用）

  在 Windows 终端（PowerShell）中：

  cd D:\Workspace\DL_HW\LAB4
  .\run_test.ps1
  .\run_all.ps1

  这是推荐方式。每个 PS1 脚本内部做了三件事：

  $ScriptDir = Split-Path -Parent $MyInvocation.MyCommand.Path  # ① 获取脚本所在目录
  Set-Location $ScriptDir                                         # ② 切换到该目录
  & $Python $Args                                                  # ③ 调用 conda python

  不需要手动 conda activate——直接指定了 python.exe 的绝对路径，PyTorch 能自动找到同环境下的 CUDA
  库。

  模式 3：WSL 写代码 → PS 跑训练（本实验采用的流程）

  WSL 终端 (vim/code 编辑)          PowerShell 终端 (执行训练)
  ┌──────────────────────┐          ┌─────────────────────────┐
  │ vim dataset.py       │          │ .\run_test.ps1           │
  │ git commit           │          │ .\run_all.ps1 -NoHibernate│
  │ xelatex 编译报告     │          │                          │
  │ (通过 powershell.exe)│          │                          │
  └──────────────────────┘          └─────────────────────────┘
           │                                    │
           └──── 共享 D:\Workspace\DL_HW\LAB4\ ─┘
                (WSL: /d/Workspace/DL_HW/LAB4/)

  两边能同时看到同一个文件系统：
  - WSL 编辑 /d/Workspace/DL_HW/LAB4/train_pretrain.py
  - PowerShell 立即运行 D:\Workspace\DL_HW\LAB4\train_pretrain.py
  - 训练日志和 checkpoint 落盘后，WSL 端立即可读

  ---
  常见问题

  Q: 不加 bash -i 会怎样？
  $ bash -c 'powershell.exe ...'
  bash: line 1: powershell.exe: command not found
  因为 powershell.exe 是你的 alias，non-interactive bash 不加载 .bashrc，别名不存在。

  Q: bash -i -c 会输出 cannot set terminal process group 怎么办？
  bash: cannot set terminal process group (-1): Inappropriate ioctl for device
  bash: no job control in this shell
  这是无害警告——WSL 的 interop 机制不支持完整的 tty
  控制。不影响命令执行，可以永久忽略。如果想隐藏，在命令前面加 2>/dev/null：
  bash -i -c 'powershell.exe ...' 2>/dev/null

  Q: 路径用 /d/ 还是 D:\？
  - Python 脚本内部（__file__、os.path.join）：都用 Python 能解析的格式。由于 Python.exe 是 Windows
  版，它不理解 /d/ 前缀。但脚本中使用 os.path.dirname(os.path.abspath(__file__))
  并在脚本自己的目录下拼接 train、test 等相对路径——这些相对路径拼接后自然就是 Windows 格式（因为
  __file__ 本身返回 Windows 路径）
  - 外部传参（--data_dir）：如果你从 PowerShell 调用，传 D:\...；如果从 WSL 调用 powershell.exe 执行
   Python，也传 D:\...
